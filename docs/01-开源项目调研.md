## 二、六维能力 × 最佳实现（源码走读地图）

| 能力 | 最佳教材 | 关键设计 | 源码入口 |
|---|---|---|---|
| ① 信息提取 | **mem0** | 两阶段：LLM 抽取候选事实 → 与已有记忆相似检索后二次 LLM 决策 | `mem0/memory/main.py` 的 `add()` → `_add_to_vector_store()` |
| ② 知识结构化 | **letta** + cognee | 分层：core memory blocks（agent 可自编辑）/ archival / recall；cognee 用本体对齐 | `letta/schemas/memory.py`、cognee `cognify` 任务图 |
| ③ 实体关系建模 | **graphiti** | 实体节点+关系边从 episode 增量抽取，去重合并（LLM 判同名/同义） | `graphiti_core/graphiti.py` 的 `add_episode()` |
| ④ 冲突消解 | **graphiti**（结构化派）+ mem0（LLM 判官派） | graphiti：双时态边失效——新边使旧边 `t_invalid`，检索只取 current；mem0：ADD/UPDATE/DELETE/NOOP 事件 | graphiti `graphiti_core/utils/maintenance/edge_operations.py`；mem0 update prompt |
| ⑤ 来源追溯 | **graphiti** | episodic 节点 = 原始内容块，每条边必须挂 episode 来源（provenance by construction） | `graphiti_core/nodes.py` 的 `EpisodicNode` |
| ⑥ 动态更新 | **graphiti**（增量）+ A-mem/letta（演化） | 增量插入 vs GraphRAG 全量重建；A-mem：新记忆触发旧记忆描述改写+自动链接 | graphiti vs graphrag 对比实验；`A-mem` 记忆演化模块 |

**核心洞察**：
1. **冲突消解有两派**——graphiti 用时间轴+失效标记（可解释、可回溯历史），mem0 用 LLM 一次性裁决（简单但不可审计）。你的系统应该抄 graphiti，把 LLM 裁决降级为辅助。
2. **溯源是 graphiti 的隐藏王牌**：episode 节点让每条知识都能回答"你从哪条消息知道的"——这正是 RFT 训练数据审计需要的性质（与你 AuditScope 数据 pipeline 直接呼应）。
3. **批处理（GraphRAG）vs 增量（graphiti/LightRAG）**是架构分水岭：Agent 记忆场景必须增量。

## 三、DIY 全链路学习路线（3 周）

### Week 1 · 源码走读（每天 1-2h，fork 只读）
- D1-2 **mem0**：跑通 `mem0.add()` local demo（Ollama）→ 读两阶段 prompt → 画出 fact 生命周期图
- D3-5 **graphiti**（重点）：`add_episode` 全程断点 → 实体去重 → 边失效 → hybrid search；输出"双时态模型笔记"
- D6-7 **cognee ECL + LightRAG 抽取**：对比两者实体抽取 prompt 与去重策略

### Week 2 · nano-memory 实操（本仓库 `nano_memory/`，目标 ~1000 行）
六个模块对应六维（见 `nano_memory/` 骨架）：
```
extract.py    ① LLM 抽取事实（mem0 两阶段 prompt 简化版）
schema.py     ② MemoryItem 数据模型 + 分层（episodic/semantic/procedural）
graph.py      ③ 实体/关系三元组 + NetworkX 内存图
resolve.py    ④ 双时态冲突消解：valid_from/valid_to + 边失效 + LLM 仲裁降级
provenance.py ⑤ 每条事实强制挂 source（episode_id/chunk/ts）
lifecycle.py  ⑥ 动态更新：增量插入、衰减、检索时 current-only 过滤
retrieve.py   混合检索：向量 + BM25 + 图游走 rerank
```
验收标准：一个 20 轮的多轮对话语料（含 3 处事实反转，如"用户换了城市/换了手机/改了偏好"），系统能正确 supersede 旧事实且每条答案可引用来源。

### Week 3 · 独立设计 + 评测
- `docs/03-独立设计方案-v0.md`：完整 schema、六维能力矩阵、与 mem0/graphiti 的差异化定位
- 评测集：**直接复用你 AuditScope 事件单语料**做记忆冲突/溯源测试——这条差异化别人没有
- 写一篇对比博客（中文写作强项）：《AI Agent 记忆系统的六维设计空间》

## 五、风险与注意
- mem0/graphiti 迭代快，走读前先 pin tag（建议各 repo 最新 release）
- graphiti 依赖 Neo4j/FalkorDB，本机 16GB 内存紧张 → 优先 FalkorDB 轻量档或 docker 单容器，或用其 SQLite/Neptune 可选后端
- LLM 调用走你现有的 DeepSeek harness（dsh）即可，成本可控
