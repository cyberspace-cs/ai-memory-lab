# MemEngine 系统设计方案 v1 · AI 记忆与知识工程

> 2026-09-20。定位承自 `01-开源项目调研.md`，实现对应 `04-代码实现方案.md`。
> 本文档是「独立设计」的完整版：学 mem0/graphiti/cognee 之后我们的差异化答案。

## 0. 一句话定位

**审计优先的增量记忆引擎**：每条知识的写入、冲突裁决、衰减都留证据链；
原生面向运维/事件单语料与中文场景；为 RFT 训练数据清洗提供可回溯底座。

## 1. 六维能力设计（自研 vs 上游差异点）

| 能力 | 上游做法 | MemEngine 做法 | 差异化 |
|---|---|---|---|
| ① 信息提取 | mem0 两阶段 LLM | **三级提取器**：LLM → 规则 → 结构化输入；产物统一 FactCandidate | 提取器可插拔，离线可跑（规则级），LLM 只做增强 |
| ② 知识结构化 | letta 分层 / cognee 本体 | 三层记忆类型（episodic/semantic/procedural）+ `(subject, predicate, object)` 三元组骨架 | 结构化粒度到三元组，检索/消解都走同一骨架 |
| ③ 实体关系建模 | graphiti 实体去重 | 归一化（大小写/别名表）+ 内存图，图接口抽象出后端 | 轻起步，接口留 Neo4j/FalkorDB |
| ④ 冲突消解 | graphiti 双时态 / mem0 LLM 裁决 | **规则优先四档裁决**：NOOP（重复）/ SUPERSEDE（时间可判）/ KEEP_BOTH（正交）/ DEFER_LLM（LLM 兜底）；每次裁决写 ResolutionLog | **裁决是一等公民**：证据链（evidence）必填，可导出审计 |
| ⑤ 来源追溯 | graphiti episodic 节点 | 无来源不入库（provenance by construction）+ 问答返回引用链 | 同 graphiti，但引用链在 API 层强制返回 |
| ⑥ 动态更新 | graphiti 增量 + A-mem 演化 | 增量插入 + 时间衰减 + superseded 不删除（history 永续） | 旧事实永续可查——训练数据标注场景需要"当时的真相" |

## 2. 核心数据模型

```python
SourceRef(episode_id, chunk_idx, ts, origin)          # ⑤ 来源，强制非空
MemoryItem(id, memory_type, content,
           subject, predicate, object,                 # ② 三元组骨架
           entities[], valid_from, valid_to,           # ④ 双时态（业务时间）
           transacted_at, source, confidence, status)  # status: current|superseded|deleted
ResolutionLog(id, item_id, new_item_id, op, evidence, judge, ts)  # ④ 裁决日志
Episode(id, text, ts, origin)                          # ⑤ 原始内容块
```

不变量（Invariants）：
1. `source is None` 的 item 拒绝入库
2. `status=superseded` 的 item 永不物理删除，`valid_to = 新事实 valid_from`
3. 同一 `(subject, predicate)` 在任一时刻最多一条 `current`
4. 每次 resolve 必产生一条 ResolutionLog，`evidence` 非空

## 3. 架构与数据流

```
            ┌──────────────────────────────────────────────┐
输入 ──────▶│ EpisodeStore（原文，append-only）             │
messages/  │        │ extract（三级提取器）                 │
docs       │        ▼                                      │
            │  FactCandidate[] ──▶ Resolver（四档裁决）      │
            │        │  evidence         │                  │
            │        │    ▲──ResolutionLog（append-only）   │
            │        ▼                                      │
            │  MemoryStore（MemoryItem 全量，含 superseded） │
            │        + EntityGraph（三元组/实体归一）         │
            │        ▼                                      │
查询 ──────▶│ Retriever：BM25 + 图扩展 → current-only →     │
            │            引用链组装                          │
            └──────────────────────────────────────────────┘
```

存储：v0 全内存 + JSON 快照；v1 sqlite；v2 向量库（sqlite-vec）+ 图库（FalkorDB）。

## 4. 冲突消解细则（系统灵魂）

输入：new: FactCandidate，conflicts: 同 (subject,predicate) 的 current MemoryItem[]

1. **NOOP**：归一化后 content 与某条 current 完全一致 → 丢弃，记日志
2. **SUPERSEDE**：new.valid_from >= conflict.valid_from 且 object 不同（如"住在上海"→"住在北京"）→ 旧条 valid_to=new.valid_from，新条入 current
3. **KEEP_BOTH**：predicate 不同或 object 正交（如"喜欢吃辣"与"住在上海"）→ 直接 ADD
4. **DEFER_LLM**：时间缺失或语义纠缠（如"喜欢甜咖啡"vs"喜欢冰美式"是否矛盾）→ 交给 judge 回调；未配置 judge → 标记 `pending` 留人工
5. **复活需复核**（v0 实现中发现补充）：新候选重提一个已被 supersede 的旧值 → 一律 DEFER——迟到复述（stale recall）与真实更正在规则层不可区分，不允许靠时间戳直接翻盘。此规则来自端到端演示暴露的真实缺陷

## 5. 检索设计

- 三路召回：BM25（关键词/中文 bigram）+ 三元组图扩展（实体邻居）+ 时间近因加权
- 融合：RRF；过滤：`status=current`（可开关拿历史）；出口：`Answer(items, citations)`，citation = fact→source→原文片段

## 6. 评测（Week 3）

- 语料 A：20 轮对话含 3 处事实反转（换城市/换手机/改偏好）→ 断言 supersede 链与引用
- 语料 B：AuditScope 事件单片段（告警→定位→结论）→ 断言知识随事件演进（初判→更正）
- 指标：current 准确率、supersede 正确率、引用可解析率、NOOP 误杀率
