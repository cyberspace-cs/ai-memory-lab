## 结构

**一、引子：为什么 Agent 需要记忆工程，而不是"存聊天记录"**（500 字）
- 钩子：Agent 上一轮说"用户住上海"，三轮后又推荐上海本地服务——错不在模型在存储
- 提出六维框架：提取/结构化/建模/消解/溯源/动态更新

**二、六维逐个拆：每维一张"设计选择谱"**（2500 字，每维 400 字左右）
1. 提取：结构化输入 → 规则 → LLM；mem0 两阶段 vs V3 单次 additive 的演进
2. 结构化：分层记忆（letta core/archival/recall）vs 三元组骨架 vs 自由文本
3. 建模：向量池 vs 实体图；实体归一与别名
4. 消解（全文重心）：LLM 裁决派（mem0 经典）vs 双时态失效派（graphiti）；我们的四档规则 + 「复活需复核」规则（实操发现的故事最好讲）
5. 溯源：graphiti episodic 节点；"没有来源的事实不允许入库"作为不变量
6. 动态更新：批处理（GraphRAG）vs 增量（graphiti/LightRAG）；衰减与印证累积

**三、实测：三条时间线让四家框架现原形**（1200 字）
- 语料 A（换城市/换手机/改偏好）+ 语料 B（事件单初判→更正）
- 各家行为对比表；nano-memory 的裁决日志输出截图/代码块
- RFT 更正对导出：记忆系统顺带成了训练数据工厂

**四、我们的答案：MemEngine 设计与取舍**（1200 字）
- 四条不变量 + 审计优先定位
- 三个踩坑实录：事务时间≠业务时间 / 同键双 current / 旧值复活
- 与上游的差异化：审计证据链、运维语料原生、中文场景

**五、开放问题**（300 字，留讨论度）
- 矛盾判定的规则覆盖率天花板在哪？
- 多租户 scope 与记忆共享的边界
- 记忆衰减该由时间驱动还是访问驱动？
